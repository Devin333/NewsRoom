# Harness Research Runtime Audit Inventory

本清单对应 `docs/prd/harness-research-runtime/00-openspec-and-audit.md`。阶段 0 只审计和标记，不删除 runtime 代码。删除工作必须等阶段 8/9 有替代 Harness + Research 覆盖后执行。

## Summary

- `keep`: 可直接服务新 Harness + Research 的领域无关底层能力或仍有清晰公共 API 价值的能力。
- `adapt`: 有可复用资产，但当前承担了旧流程控制、旧 board/paper 语义、旧接口兼容或位置不合适，需要降级为 Harness worker、port adapter、domain service 或测试夹具。
- `delete`: 只服务旧 board、旧 paper_radar、旧 paper API/UI、旧兼容、旧控制流或业务污染框架层的资产。

## Skill Evolution Notes

Stage 3A should reuse these assets instead of rewriting them:

- `framework/skills/package`: candidate package load, registry metadata, manifest and package validation.
- `framework/skills/validation`: input/output JSON Schema gate.
- `framework/skills/quality`: deterministic quality gates for candidate and eval results.
- `framework/skills/evaluation`: held-out example replay starting point.
- `framework/skills/runtime`: execution wrapper, adapted so production composition does not silently use `MockSkillExecutor`.
- `business/foundation/skills`: business skill content/eval examples, not production promotion authority.

Harness must own candidate selection, validation orchestration, eval thresholds, promotion, versioned release and rollback. LLM output can only create candidate data.
